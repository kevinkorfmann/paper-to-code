# PLINK 2 LD pruning: pair-check order can change how many markers survive

An original deterministic diagnostic using the actual checksum-pinned **PLINK
2.0.0-b.1.2LM** executable. The same three-marker input retains **A and C** with
`--indep-order 1` but **only A** with `--indep-order 2`. Mode 2 is the documented
default. This is an inference-pipeline preprocessing operation, not a fitted
ancestry, recombination rate, population history, or estimate of independent
information.

## Input and estimand

The toy has 64 named, diploid samples treated as founders, three biallelic markers
at positions 1, 2 and 3 of chromosome 1, and no missing calls. Each of these four
ALT-dosage rows appears 16 times:

| A | B | C | Sample count |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 16 |
| 0 | 1 | 2 | 16 |
| 2 | 1 | 0 | 16 |
| 2 | 2 | 2 | 16 |

A and C are independent in this exact count table, and B=(A+C)/2. All allele
frequencies are 0.5. Var(A)=Var(C)=1, Var(B)=1/2 and Cov(A,B)=Cov(B,C)=1/2, so
squared dosage correlations are **r²_AB=r²_BC=1/2**, **r²_AC=0**. The code
recomputes them with exact rational arithmetic. These are deliberately constructed
genotypes, not sampled individuals or a biological population. A and C depart
from Hardy–Weinberg proportions. HWE is not needed to compute these empirical
correlations. There is no seed because there is no randomness.

The requested output is a list of markers retained by PLINK's greedy pruning
procedure, conditional on calls, founder status, marker order, window, threshold,
allele-frequency tie handling, pair-scan mode and version. No statistical
uncertainty interval is computed. The fixture exceeds the tool's 50-founder
minimum without overriding that safeguard.

## Actual command and result

The wrapper creates a temporary VCF and calls:

```text
plink2 --vcf input.vcf --indep-pairwise 3 1 0.2 --indep-order MODE \
  --r2-unphased square --threads 1 --memory 640 --out result
```

Both modes use a window of three variants, a one-variant step and strict removal
threshold `r² > 0.2`. Mode 1 imitates PLINK 1.x pair checking, whereas mode 2 scans
backwards inside each window. They are not two different LD estimators.

| Pair-scan mode | Retained | Removed |
| --- | --- | --- |
| 1 | A, C | B |
| 2 | A | B, C |

The unfiltered LD matrix reported by the same run is identical in both cases.
Pruning writes `.prune.in` and `.prune.out` **lists**. It does not filter other
operations in the same invocation. Use the retained list with `--extract` in a
subsequent command when filtering is intended.

An independent exhaustive check of all eight subsets finds that `{A,C}` is the
unique largest subset satisfying the pairwise threshold. The mode-2 result can
even be extended by C, so it is not maximal in this fixture. This is a concrete
counterexample to interpreting the output as a maximum-cardinality solution,
not a claim that mode 1 is always better. Finite windows also do not guarantee
all retained markers are globally uncorrelated. Pruning does not establish
statistical independence, and weak pairwise correlation does not exclude
higher-order dependence.

Controls permute the marker patterns among the three positions. With B first,
both modes retain only B. Raising the threshold to 0.5 or 0.6 retains all three
markers, including the equality case because the cutoff is strict. Reversing
sample order or A's allele coding leaves squared correlations and the baseline
pruning result unchanged. These exact fixtures demonstrate implementation
behavior, not the reliability of LD estimates from real data.

## Reproduce

From the repository root, use Linux x86-64 and **CPython 3.14.5** (the root
`.python-version`). No Python packages are required. The reused installer checks
the official archive and executable SHA-256 hashes and installs the unmodified
binary only under the ignored local cache. It preserves the included license.

```bash
python -m examples.inference_showcase.plink_king.install
python -m unittest examples.inference_showcase.plink_prune_order.test_demo -v
python -m examples.inference_showcase.plink_prune_order.demo
python -m examples.inference_showcase.plink_prune_order.demo --check-sample
```

[Actual output](sample_output.json) records the version, full matrices and lists.
The existing PLINK CI job runs the tests and byte-for-byte output check. The 18
tests include all six marker permutations in both modes, a separately derived
sample-pair-difference covariance oracle, exhaustive subset search, threshold
boundary checks, allele/sample invariances and invalid-input rejection. The
synthetic VCF is generated by `vcf_text(panel())` without downloads or private
data. We do not copy or reimplement PLINK's pruning algorithm.
